# Day 1: Training with VS Code and Claude Code

## What I learned

- **VS Code** is a free code editor made by Microsoft.
- We can build customized tools for any process the company currently does manually. Manual processes create unexpected errors, so VS Code can help improve the process by developing a tool.
- VS Code can work with large data, is very handy for getting things done, and makes it easy to flag mistakes and errors in the process.
- VS Code can suggest better options and better solutions for tools and processes.
- **Git** is a tool for tracking changes made in code.
- VS Code has extensions for Java, Python, Claude Code, etc., so no matter which language you build the tool in, it will help.
- VS Code can read the folders and files on the computer, making it easy to get the particular data needed.

## Git commands I learned

| Command | What it does |
|---|---|
| `git init -b main` | Turns a folder into a Git repository with a `main` branch |
| `git config --global user.name "..."` | Sets the name shown on my commits |
| `git add .` | Stages all changed files for the next commit |
| `git commit -m "message"` | Saves a snapshot with a message describing the change |
| `git commit -am "message"` | Stages changes to tracked files and commits in one step |
| `git remote add origin <URL>` | Connects the local folder to a GitHub repository |
| `git push -u origin main` | Uploads commits to GitHub the first time (later just `git push`) |
| `git switch -c practice` | Creates a new branch called `practice` and switches to it |
| `git switch main` | Switches back to the `main` branch |
| `git merge practice` | Brings the commits from `practice` into the current branch |

My routine after changing files: `git add .` → `git commit -m "..."` → `git push`

# Day 2: Git and GitHub

## What I learned

- **Repository (repo):** a project folder.
- **Commit:** a save point. Each commit has a short message saying what you changed.
- **Push:** uploading your saves from your computer to GitHub.
- **Branch:** a separate copy of your work where you can try things without touching the main version. Like making a photocopy of your homework to experiment on.
- **Merge:** taking the changes from that copy and putting them back into the main version.
- **VS Code with the Claude Code extension** is like Google Assistant on your phone: you ask in plain words and it does the work, but for files, folders and commands on your computer.

## What I did

1. Created a GitHub account with my work email.
2. Finished the "Introduction to GitHub" exercise.
3. Created a new repository and connected my Day 1 folder to it, with Claude Code explaining each command before running it.
4. Changed `notes.md`, then committed and pushed at least 3 times with clear messages.
5. Made a branch called `practice`, changed something there, then merged it back.

## Be careful

- GitHub is meant for **code and small files**, not big videos or huge folders.
- If a repository is **public**, anyone on the internet can see the files. If it's **private**, only you and the people you invite can see them.
- **Never upload passwords, secret keys or private company data**, even to a private repository.
